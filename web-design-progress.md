## Search page desktop redesign (2026-10-19, commit 8013a7b, deployed live)

- **2026-10-19 — The desktop search page was the mobile page wearing a desktop layout**: the shared `Chips` pills (40px+ tall, horizontal-scroll-only) were used as sidebar filter controls; the "Searching for: (empty)" display proved the page could never see what the user typed in the navbar (DesktopShell owns its own local `query` state — `useSearch` has a separate one, nothing connects them); and the results column showed one giant card because the shared `ProductCard` hardcodes `width: "48%"`, which in a ~1500px column is a 720px card. Rebuilt `Search.web.tsx` as a real desktop layout: compact wrapping filter chips in a 200px sidebar (Condition / Sort / Category), a page-owned `SearchBar`, a segmented Products/Sellers switch, 4-up "23%" product tiles (the same sizing rule as `StreamCardDesktop`), and a proper seller row list with `InitialsAvatar`.
- **Two behavioral upgrades shipped with the redesign**: (1) search + category are now SERVER-side — `listProducts({ q, categoryId })` including top-level children expansion, the same expansion rule as `loadCardsForCategory` in catalog.ts — instead of client-side filtering of a fixed 40-product fetch; (2) price-less products sort to the END of price sorts (`?? Infinity` asc / `?? -Infinity` desc) instead of the front (`?? 0` bug inherited from the old page).
- **Layout carry-forward**: desktop `.web.tsx` files may use `boxShadow` string props and percentage widths directly (web-only module); the new local compact `FilterChip` (~24px pill, wraps, brand-on-active) is the established filter-chip shape for desktop pages — don't reach for the shared phone-sized `Chips` as a desktop sidebar control again.
